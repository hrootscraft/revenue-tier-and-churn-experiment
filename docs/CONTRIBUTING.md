# Contributing

## Setup

```bash
git clone https://github.com/hrootscraft/revenue-tier-and-churn-experiment
cd revenue-tier-and-churn-experiment
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"          # package + pytest, ruff, jupyter tooling
make test                        # ~1 minute: unit tests on a 1,200-client simulation
make all                         # ~3 minutes: full pipeline -> data/, results/, reports/figures/
```

Python 3.10–3.12 (EconML 0.15 does not yet publish 3.13 wheels). The pipeline uses all cores
through scikit-learn's OpenMP threading; set `OMP_NUM_THREADS=1` if you run several in parallel.

## Layout

```
configs/default.yaml        every tunable number: population, fee tiers, design, planted truth, analysis
src/tierlift/
  config.py                 typed, validated loader for the YAML
  fees.py                   tier schedule, blended rates, distance to the next tier
  features.py               the pre-treatment feature matrix every model shares
  simulate/                 population -> assignment -> potential outcomes
  experiment/               ATE estimators (ate.py), design checks (design.py), robustness tests,
                            and the observational counterfactual (observational.py)
  uplift/                   learners.py (model zoo), evaluate.py (Qini/AUUC/RATE/BLP), policy.py
  economics/                revenue decomposition and rollout comparison
  durability/               survival analysis of engagement and the ROI projection
  validation/checks.py      data-quality gates that run before any analysis
  plots.py                  every figure
  pipeline.py               run_all(): the one function that produces results/ and figures
  montecarlo.py             replication over seeds (estimator calibration; benchmark stability)
  cli.py                    `tierlift run-all | simulate | montecarlo`
notebooks/                  thin narrative layer; all logic is imported from src/
docs/learn/                 one write-up per method, with worked examples and exercises
docs/DECISIONS.md           why each design choice was made
results/                    small CSV/JSON tables the README quotes (committed; regenerated by `make all`)
reports/figures/            PNGs (committed; regenerated by `make all`)
tests/                      unit tests + one end-to-end test marked `slow`
```

## Conventions

* **No analysis code in notebooks.** If a notebook needs a calculation, add a function to
  `src/tierlift` with a docstring and a test, then import it. The pipeline and the notebooks
  must never disagree.
* **Truth stays in `truth.parquet`.** Observed tables (`experiment`, `weekly`, `clients`)
  never carry potential outcomes, planted effects or lapse times.
  `tests/test_simulate.py::test_truth_not_in_observed_tables` enforces it.
* **Only pre-treatment features.** `features.py` is the single source; `validation/checks.py`
  fails the run if a post-treatment column sneaks in.
* **Every estimator returns an `Estimate`** (`experiment/ate.py`) with absolute and relative
  effects and delta-method SEs, so tables are built the same way everywhere.
* **Every learner goes through `fit_crossfit`**, so scores are out-of-fold before any
  evaluation.
* **Numbers in the README come from `results/`.** If you change the simulation, run
  `make all`, then `tierlift montecarlo` to re-check calibration, then update the README from
  `results/headline.json`.
* Style: `ruff check` and `ruff format` (100-char lines). Docstrings explain *why*, not *what*.

## Adding a learner

1. Add a `LearnerSpec` to `model_zoo()` in `uplift/learners.py`. Its `build(seed)` must return
   an object with `.fit(Y, T, X=...)` and `.effect(X)` (the EconML interface; wrap anything
   else in a small adapter class).
2. Give it a colour slot in `plots.LEARNER_COLORS` (eight slots exist; do not generate hues).
3. Run `make fast`; it appears in `results/uplift_benchmark.csv` and the Qini figure.
4. If it is a new *family* of method, add a `docs/learn/` write-up in the same shape as the
   others: intuition, a worked example small enough to do by hand, the math, where it shows
   up in the results, pitfalls, exercises with answers.

## Adding a check

`validation/checks.py`: write a function returning `CheckResult`, add it to `run_all_checks`.
Blocking checks stop the pipeline; non-blocking ones are reported in
`results/data_quality_checks.csv`.

## Changing the planted truth

Everything is in `configs/default.yaml` under `truth:`. After a change:

```bash
tierlift montecarlo --n-seeds 40          # is the estimator still unbiased and calibrated?
# results/montecarlo_extra.csv names the new showcase seed (median rule)
# set `seed:` in configs/default.yaml to it, then
make all
tierlift montecarlo --benchmark --n-seeds 5 --workers 2   # is the leaderboard stable?
```

and record the reason in `docs/DECISIONS.md`.
